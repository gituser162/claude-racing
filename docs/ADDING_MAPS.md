# Як додати нову мапу (трасу)

Документ має дві частини:
1. **Для тебе:** що написати Claude, щоб отримати нову мапу.
2. **Для Claude:** технічна інструкція. Claude читає її перед тим, як додавати мапу.

---

## Частина 1. Для тебе: шаблон запиту

```
Нова мапа
Назва: …
Сетинг / настрій: … (за замовчуванням — нічне кіберпанк-місто, див. DESIGN.md)
Характер траси: … (швидка з плавними поворотами / технічна зі шпильками / з трамплінами …)
Особливі місця: … (тунель, міст, розв'язка, зріз …)
Довжина кола: … (за замовчуванням ~45–60 с; або «1 коло від А до Б» — спринт)
Короткий опис для меню (один рядок): …
```

**Правила:**
- **Стиль** — «сучасний PS1» (див. «Візуальні правила» в `DESIGN.md`). Нічне кіберпанк-місто — обов'язкова умова.
- **Бар'єри** ставляться автоматично із зовнішнього боку крутих поворотів; на пологих їх немає — звідти можна вилетіти.
- У меню мапа з'являється карткою на екрані «ОБЕРИ ТРАСУ» (після вибору гонщика); тип і довжина рахуються самі.
- Траса буває **кільцева** (3 кола) або **спринт** — від старту до фінішу за один раз (як «Спіраль»).

**Як перевіряти:** Claude будує трасу, перевіряє, що боти проходять коло, і показує скріншоти. Ти запускаєш гру й кажеш, що не так.

---

## Частина 2. Для Claude: технічна інструкція

### Де що лежить (одна мапа = сцена траси + ресурс + 1 рядок)

| Що | Шлях | Примітка |
|---|---|---|
| Сцена траси | `scenes/track/<id>.tscn` | Корінь — `Node3D` зі скриптом `scripts/race/track.gd` (клас `Track`), дочірній `Path3D` з іменем `TrackPath` (крива по центру дороги) і дорога (`CSGPolygon3D` по цій кривій). Найпростіше — скопіювати `test_track.tscn` і змінити криву. |
| Дані мапи | `resources/maps/<NN>_<id>.tres` | Ресурс `MapData` (`scripts/data/map_data.gd`): `id`, `display_name`, `description` (один рядок), `scene_path`, `laps` (3; для спринту — 1). |
| Реєстрація | `scripts/autoload/game.gd` → `MAP_PATHS` | Додати рядок зі шляхом до `.tres`. **Саме шлях, не `preload`** — інакше цикл залежностей і експортована гра не запускається (як і з гонщиками). |

### Як це працює
- `Game.MAPS` — завантажені `MapData`, `Game.selected_map` — обрана в меню.
- Сцена гонки (`scenes/main.tscn`) і фон меню містять вузол `TestTrack`. Одразу після створення сцени (`NOTIFICATION_SCENE_INSTANTIATED`) `Game.swap_in_selected_map($TestTrack)` ставить на його місце трасу обраної мапи з тим самим іменем, тож увесь код, що звертається до `$TestTrack`, працює без змін.
- Місто, ліхтарі, опори, арки, білборди й бар'єри будує `track.gd` вздовж кривої — нова траса отримує їх автоматично. Параметри (`road_width`, `checkpoint_count`, щільність міста, `barrier_max_radius` тощо) — експортовані змінні `Track`.
- **Тип траси** (експортовані змінні `Track` на корені сцени):
  - `elevated` — `true`: естакада (опори, місто внизу на `city_floor_y`, з траси можна впасти); `false`: вулиця на рівні землі (`city_floor_y = 0`, підлога `CityFloor` на рівні дороги).
  - `barrier_mode` — `SHARP_CORNERS`: бар'єри лише із зовнішнього боку крутих поворотів; `FULL`: суцільні відбійники з обох боків (видима стіна — CSG-смуга вздовж кривої, зіткнення — короткі коробки на шарі 5).
  - `frontage_buildings` + `sidewalk_width` — будинки фасадами вздовж обох боків траси.
  - `keep_clear` — зони без забудови й білбордів: `Vector3(x, z, радіус)`.
  - `billboard_lateral` — відстань білбордів від центру дороги.
  - `lamp_spacing`, `arch_spacing`, `billboard_spacing`, `pillar_spacing` = 0 — вимикають ліхтарі, арки, білборди, опори.
  - `menu_showcase` — де в меню стоїть подіум з гонщиком (за замовчуванням на дорозі за 30 м перед стартом).
  - `menu_preview_center`, `menu_preview_radius`, `menu_preview_height` — обліт камери на екрані «ОБЕРИ ТРАСУ» (камера не має опинитись у будинках — перевір скріншотом `shots_menu.gd`).
- **Спринт** (група «Тип траси»): `closed = false`; `start_offset` — де на кривій лінія старту (позаду — сітка: 4 ряди, ~26 м + машина, уся на дорозі!); `finish_runout` — скільки кривої за фінішем (зона гальмування); чекпоінти рівно від старту (0) до фінішу (останній). У `MapData` — `laps = 1` (ультімейт тоді доступний одразу, у HUD і результатах немає «кращого кола»). Після фінішу боти й автопілот гравця м'яко гальмують (`BotDriver.brake_to_stop`). Кінець кривої — упор (див. `spiral_features.gd`). Дорога (`Road` і смуги) — `path_joined = false`.
  - `fall_limit_y` — нижче цієї висоти респаун (для високих трас — нижче землі); `respawn_off_road` — респаун, щойно машина далеко збоку від дороги чи нижче неї (перелетіла через відбійник).
  - `floor_height`, `floor_base_y` — для вежі: HUD показує поверх замість кола (`Track.get_floor`).
- **Траса над/під собою** (спіраль, розв'язка): переріз дороги без крену — `path_rotation = 1` (PATH) у `Road`/смугах (відбійники беруть його з `Road`); плита тонка (1 м), а не 6 м, як на естакаді; між плитами ≥ ~11 м. Будинки з шейдером `psx_building` на землі нижче нуля — параметр `ground_y` (інакше без вікон).
- **Особливі місця** мапи — дочірній вузол зі скриптом, що має метод `build_features(track: Track)`: `track.gd` викликає його в кінці свого `_ready`, коли крива вже готова. Приклад — `scripts/race/street_features.gd` (ділянки задаються точками світу, офсет по трасі — `track.get_offset_of`).
- **Крива з кутів:** `tools/track_layout.py` будує ламану з вершин (x, z, радіус скруглення), друкує довжину й малює план згори; точки йдуть у `Curve3D` сцени (перша точка повторюється в кінці, щоб коло замкнулось).
- **Спіраль:** `tools/spiral_layout.py` — дах → заїзд → спіраль з плавним ухилом → вихід; перевіряє вертикальний запас там, де траса проходить над собою.

### Кроки перевірки
1. Імпорт без помилок (`--headless --editor --quit`).
2. Сцена гонки з цією мапою: машини стоять на старті, чекпоінти рахуються, коло зараховується.
3. Боти проходять коло без масових падінь (одне коло з усіма машинами).
4. Скріншоти: екран «ОБЕРИ ТРАСУ» з новою мапою (`tools/tests/shots_menu.gd`), старт, кілька характерних місць траси.
5. Оновити `DESIGN.md` (розділ «Траса»).
