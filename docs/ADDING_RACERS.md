# Як додати нового гонщика

Документ має дві частини:
1. **Для тебе:** що написати Claude, щоб отримати нового гонщика.
2. **Для Claude:** технічна інструкція. Claude читає її перед тим, як додавати гонщика.

---

## Частина 1. Для тебе: шаблон запиту

Скопіюй, заповни і надішли Claude. Порожні пункти Claude заповнить сам і запропонує на погодження.

```
Новий гонщик
Ім'я: …
Мем / ідея: … (на що посилається, чому смішно)
Модель: … (як виглядає; з чого складається; розмір: маленький / як карт / великий)
Колір: …
Характеристики (Ш/Р/К/В, кожна 1–3, сума 8): …
Q (легкий, з перезарядкою): назва — що робить
E (ультімейт, раз за гонку на останньому колі): назва — що робить
Короткий опис для меню: …
```

**Правила, щоб гонщик вписався в гру:**
- **Характеристики:** Ш — швидкість, Р — розгін, К — керування, В — вага. Кожна від 1 до 3, сума завжди **8**. Вага впливає на зіткнення: важкий таранить, легкого відкидає.
- **Q** — щось корисне, але не вирішальне. Перезарядка 6–10 с.
- **E** — яскравий момент гонки, одноразовий, відкривається тільки на останньому колі.
- **Стиль:** PS1, low-poly, не мультяшно (див. `DESIGN.md`). Мемність — в ідеї й формі, а не в яскравих кольорах.
- **Без справжніх логотипів і брендів:** можна впізнаваний стиль, але назви й емблеми вигадані.

**Як перевіряти:** Claude додає гонщика й ганяє тестові гонки. Ти запускаєш гру й кажеш, що не так («модель задрібна», «скіл заслабкий»).

---

## Частина 2. Для Claude: технічна інструкція

### Де що лежить (один гонщик = 4 файли + 1 рядок)

| Що | Шлях | Примітка |
|---|---|---|
| Дані гонщика | `resources/racers/<NN>_<id>.tres` | `RacerData`: ім'я, опис, колір, характеристики, модель, габарит, скіли |
| Модель | `scenes/racers/<id>/model.tscn` | Лише візуал, без фізики |
| Скіл Q | `scripts/skills/<id>_q.gd` | `extends Skill` |
| Скіл E | `scripts/skills/<id>_e.gd` | `extends Skill` (ультімейт) |
| Перешкоди/снаряди (якщо треба) | `scenes/skills/<id>_<name>.tscn` | Корінь `Area3D` зі скриптом `Hazard` |
| Реєстрація | `scripts/autoload/game.gd` → `RACER_PATHS` | Додати рядок зі шляхом до `.tres`: явний список потрібен для експорту |

Зразки: Ракета (`01_rocket.tres`, `turbo_skill.gd`, `jet_jump_skill.gd`) та 7 мемних гонщиків (`02_courier` … `08_capybara`, скіли `scripts/skills/<id>_q.gd` / `<id>_e.gd`).
Приклади типових скілів: перешкода позаду — `courier_q.gd`; ефект на всіх попереду — `courier_e.gd`; поштовх навколо — `cat_q.gd`;
перенос уперед — `cat_e.gd`; тривалий ефект з `_physics_process` — `tractor_q.gd`, `tractor_e.gd`; власний об'єкт, що летить трасою — `goose_flock.gd`.

**Моделі** можна генерувати скриптом (не обов'язково): опис деталей списком → `.tscn`. Найпростіше — скопіювати схожу модель і змінити.

### 1. Дані гонщика (`.tres`)
Поля `RacerData` (`scripts/data/racer_data.gd`):
- `id` (латиницею, `&"cat"`), `display_name`, `bio`, `car_color`;
- `speed`, `acceleration`, `handling`, `weight`: 1–3, сума 8;
- `model_scene`, `footprint`: ширина × довжина для зіткнень, м. Карт — `1.7 × 2.9`, фургон ~`2.2 × 4.2`, кіт ~`1.2 × 1.8`;
- `skill_q_name`, `skill_q_description`, `skill_q_script`, і так само для `skill_e_*`.

### 2. Модель (`model.tscn`)
- **Корінь:** `Node3D` з ім'ям `Model`. **«Перед» дивиться в −Z**, низ (колеса, лапи) на `y = 0`. Центр приблизно над точкою (0, 0, 0).
- **Будуємо з примітивів** (`BoxMesh`, `CylinderMesh` з `radial_segments` 6–8, `SphereMesh` з малою кількістю сегментів). 30–300 трикутників на деталь, PS1-стиль.
- **Матеріали:** тільки `ShaderMaterial` з `res://resources/shaders/psx.gdshader` (параметри `albedo`, `emission`, `emission_energy`). `StandardMaterial3D` не використовувати. Кольори приглушені, яскраве лише світло й неон (`emission_energy` 2–4).
- **Групи вузлів**, які шукає `Car` (через `groups=["..."]` у `.tscn`):
  - `paint` — `MeshInstance3D`, які фарбуються в `car_color`;
  - `steer` — вузли, що повертаються з кермом (передні колеса, голова кота тощо);
  - `spin` — вузли, що крутяться навколо X зі швидкістю (колеса).
- **Фари/вогні:** маленькі `BoxMesh` з емісією, бажано є в кожного, щоб гонщика було видно вночі.
- **Не додавати:** фізику, колізії, скрипти. Підсвічування знизу, вогонь турбо і реактивне полум'я вже є в `car.tscn` і самі підлаштовуються під `footprint`.
- **Pitfall:** у `.tscn` `Transform3D(...)` записується **рядками базису**, а не стовпцями. Простіше задавати `rotation = Vector3(...)`.

### 3. Скіли
Базовий клас `Skill` (`scripts/skills/skill.gd`). Перевизначити:
- `_activate()` — що робить скіл;
- `bot_wants_to_use(driver: BotDriver) -> bool` — коли бот його вмикає. Викликається лише, коли скіл готовий;
- за потреби `_can_use() -> bool` — додаткова умова (наприклад, тільки на землі);
- у `_init()` задати `cooldown` для Q (6–10 с). Для E `is_ultimate` ставиться автоматично.

**Помічники в `Skill`:**
`other_cars()`, `car_ahead(max_m)`, `car_behind(max_m)`, `cars_within(radius)`, `cars_ahead_within(distance)`, `get_track()`, `transform_behind(distance)`, `spawn_in_world(scene, transform)`.

**Що можна робити з машиною** (`scripts/car/car.gd`):

| Метод | Що робить |
|---|---|
| `add_boost(mult, duration, kick)` | Турбо: макс. швидкість × mult + поштовх |
| `jet_jump(up_speed, forward, air_steer)` | Стрибок |
| `apply_slow(factor, duration)` | Сповільнення (не діє під захистом) |
| `spin_out(duration)` | Розкрутка, втрата керування (не діє під захистом) |
| `push(velocity_change)` | Поштовх у світових координатах (не діє під захистом) |
| `set_protected(duration)` | Захист від сповільнень, розкруток, поштовхів |
| `set_ghost(duration)` | Проходить крізь машини |
| `set_mass_multiplier(mult, duration)` | Тимчасово важча/легша (зіткнення) |
| `set_steer_multiplier(mult, duration)` | Тимчасово чутливіше/«ватне» кермо |
| `warp(transform)` | Перенести в точку траси, зберігши швидкість (на відміну від `teleport`) |
| `nudge_heading(angle)` | Плавно повернути курс |
| `teleport(transform)` / `respawn()` | Перемістити |
| `get_forward()`, `get_speed()`, `is_grounded()`, `body.global_position`, `ball.linear_velocity` | Стан |

**Траса** (`Track`): `get_offset_of(pos)` → метри від старту; `get_transform_at(offset, lateral, height)` → точка на дорозі за ходом руху; `length`.

**Помічники бота** (`BotDriver`): `is_on_straight()`, `car_ahead_distance()`.

**Перешкоди й снаряди:** сцена з коренем `Area3D` + скрипт `res://scripts/skills/hazard.gd` + `CollisionShape3D` + модель. Налаштування в інспекторі:
- `effect` = SLOW / SPIN / PUSH_UP, `strength`, `duration`;
- `single_use`, `lifetime`;
- `speed` — для снаряду, що летить уперед.

Ставиться так: `spawn_in_world(load("res://scenes/skills/<id>_<name>.tscn"), transform_behind(4.0))`. Свою машину перешкода не чіпає першу секунду.
**Важливо:** сцени й скрипти перешкод у скілах завантажувати через `load()`, а **не** `preload()`. Інакше утворюється циклічна залежність скриптів (Skill → Hazard → Car → Skill), і Godot видає помилку «Parse Error: Busy».

**Якщо потрібен ефект, якого немає:** додати новий метод у `Car`, у тому ж стилі (таймер у `_tick_effects`, перевірка `is_protected()` для шкідливих). Потім додати рядок у таблицю вище.

**Шаблон скіла:**
```gdscript
extends Skill
## <Гонщик>, Q — «<Назва>»: <що робить>.

@export var duration: float = 2.0

func _init() -> void:
	cooldown = 8.0

func _activate() -> void:
	var target := car_ahead(40.0)
	if target:
		target.spin_out(0.9)

func bot_wants_to_use(driver: BotDriver) -> bool:
	return car_ahead(25.0) != null and randf() < 0.05
```

### 4. Реєстрація
Додати рядок `"res://resources/racers/<NN>_<id>.tres",` у `RACER_PATHS` (`scripts/autoload/game.gd`). Саме шлях, **не** `preload` — інакше виникає цикл залежностей і експортована гра не запускається. Боти беруть гонщиків з цього списку (`Game.RACERS`).

### 5. Перевірка (обов'язково перед тим, як віддати)
1. **Імпорт без помилок:** `godot --headless --editor --quit` у копії проєкту.
2. **Повна гонка** автопілотом (`--fixed-fps 60`, тестовий скрипт): усі фінішують, скіли спрацьовують, немає `SCRIPT ERROR`.
3. **Знімок екрана** моделі в грі (xvfb + `--rendering-driver opengl3`): перевірити розмір, напрямок «вперед», що модель стоїть на дорозі.
4. **Тестові скрипти**, що завантажуються через `-s`, не повинні мати статичних типів `Car`/`BotDriver`/`Game`: autoload ще не зареєстрований. Використовувати `load(...)` і нетипізовані змінні.
5. **Перед записом у проєкт користувача** перевірити `mtime` файлів (`expectedMtimeMs`), щоб не затерти його правки.
6. **Оновити `DESIGN.md`:** таблицю гонщиків і прогрес.
